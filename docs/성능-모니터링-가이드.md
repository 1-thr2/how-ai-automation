# 성능 모니터링 가이드

## 🎯 초보자를 위한 설명

**성능 모니터링**이란?
- 웹사이트가 얼마나 빠르게 로딩되는지 측정
- 사용자가 어떤 페이지를 방문하는지 추적
- 에러가 발생하면 즉시 알림

**왜 필요한가요?**
1. 🚀 **사용자 경험**: 느린 페이지는 사용자 이탈
2. 🐛 **에러 추적**: 문제 발생 시 빠른 대응
3. 📊 **데이터 기반 개선**: 숫자로 개선 효과 확인
4. 💰 **비용 최적화**: 불필요한 API 호출 감소

## 📦 추천 도구

**장점:**
- ✅ Vercel 배포 시 자동 활성화

  - CLS (Cumulative Layout Shift): 레이아웃 변경 정도
- **페이지 방문 수**
- **고유 방문자 수**
- **국가별/기기별 통계**

### 3. Sentry (에러 모니터링, 무료 플랜 있음)

**장점:**
- 🐛 에러 발생 시 즉시 알림
- 📊 에러 발생 빈도 추적
- 🔍 에러 스택 트레이스 자동 수집

**설치:**

```bash
npx @sentry/wizard@latest -i nextjs
```

위 명령어 실행하면 자동으로 설정 완료!

**환경변수 추가:**

```env
# .env.local
NEXT_PUBLIC_SENTRY_DSN=https://...@sentry.io/...
SENTRY_AUTH_TOKEN=...
```

**사용 예:**

```typescript
import * as Sentry from '@sentry/nextjs';

try {
  // 위험한 작업
  await riskyOperation();
} catch (error) {
  // 에러 자동으로 Sentry에 전송
  Sentry.captureException(error);
  throw error;
}
```

### 프로젝트 내장 모니터링

이미 `src/lib/monitoring/` 폴더에 모니터링 시스템이 있습니다!

```typescript
// src/lib/monitoring/collector.ts
import { startAPIMetrics } from '@/lib/monitoring/collector';

export async function POST(req: Request) {
  // 메트릭 수집 시작
  const metrics = startAPIMetrics('/api/agent-orchestrator');

  try {
    // ... API 로직 ...

    // 메트릭 기록
    metrics
      .recordModel('gpt-4o', 1500)
      .recordRAG(3, 10, 2)
      .recordResults(8);

  } catch (error) {
    metrics.recordError(error);
  }

  return metrics.finish();
}
```

**대시보드 확인:**
```
http://localhost:3005/api/dashboard
```

비밀번호: 환경변수 `DASHBOARD_PASSWORD` (기본값: admin123)

**측정 항목:**
- API 호출 수
- 평균 응답 시간
- 토큰 사용량
- RAG 검색 횟수
- 에러 발생 수

## 🎯 핵심 지표 (Web Vitals)

### LCP (Largest Contentful Paint)

**의미:** 페이지의 가장 큰 콘텐츠가 보이는 시간

**목표:**
- ✅ 좋음: 2.5초 이하
- ⚠️ 개선 필요: 2.5~4초
- ❌ 나쁨: 4초 이상

**개선 방법:**
- 이미지 최적화 (Next.js Image)
- 서버 응답 시간 단축
- 중요하지 않은 CSS 지연 로딩

### FID (First Input Delay)

**의미:** 사용자가 버튼 클릭 시 반응 시간

**목표:**
- ✅ 좋음: 100ms 이하
- ⚠️ 개선 필요: 100~300ms
- ❌ 나쁨: 300ms 이상

**개선 방법:**
- 큰 JavaScript 파일 분할
- 긴 작업을 Web Worker로 이동
- 불필요한 라이브러리 제거

### CLS (Cumulative Layout Shift)

**의미:** 페이지 레이아웃이 얼마나 많이 변하는지

**목표:**
- ✅ 좋음: 0.1 이하
- ⚠️ 개선 필요: 0.1~0.25
- ❌ 나쁨: 0.25 이상

**개선 방법:**
- 이미지/비디오에 width, height 지정
- 폰트 로딩 최적화 (font-display: swap)
- 동적 콘텐츠에 미리 공간 확보
