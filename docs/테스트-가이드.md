# 테스트 가이드

## 🎯 초보자를 위한 설명

**테스트**란?
- 코드가 제대로 작동하는지 자동으로 확인하는 프로그램
- 수동으로 일일이 확인하는 대신, 코드로 검증
- 버그를 미리 발견하고, 리팩토링 시 안전장치 역할

**왜 필요한가요?**
1. 🐛 **버그 조기 발견**: 배포 전에 문제를 찾음
2. 🔒 **리팩토링 안정성**: 코드 수정 시 기존 기능이 깨지지 않음을 확인
3. 📚 **문서화**: 테스트 코드가 함수 사용법을 보여줌
4. 🚀 **자신감**: 코드 변경에 대한 두려움 감소

## 📦 설치

테스트 라이브러리를 설치하세요:

```bash
npm install
```

이미 `package.json`에 필요한 패키지가 추가되어 있습니다:
- `jest`: 테스트 프레임워크
- `@testing-library/react`: React 컴포넌트 테스트
- `@testing-library/jest-dom`: DOM 검증 유틸리티

파일을 수정하면 관련 테스트만 자동으로 다시 실행됩니다!

### 커버리지 확인

```bash
# 테스트 커버리지 리포트 생성
npm run test:coverage
```

결과:
```
----------------------|---------|----------|---------|---------|
```

## 📝 테스트 작성법

### 기본 구조

```typescript
// src/lib/__tests__/example.test.ts

/**
 * describe = 테스트 그룹
 * 비슷한 테스트들을 묶어서 관리
 */
describe('함수 이름 또는 기능', () => {

  /**
   * it 또는 test = 개별 테스트 케이스
   * "~해야 한다" 형태로 작성
   */
  it('특정 상황에서 예상된 결과를 반환해야 함', () => {
    // 1. 준비 (Arrange): 테스트할 데이터 설정
    const input = '테스트 입력';

    // 2. 실행 (Act): 함수 실행
    const result = myFunction(input);

    // 3. 검증 (Assert): 결과 확인
    expect(result).toBe('예상 결과');
  });
});
```

### 실제 예시

```typescript
// src/lib/__tests__/env-validator.test.ts
import { getEnvStatus } from '../env-validator';

describe('getEnvStatus', () => {
  it('환경변수 상태를 올바르게 반환해야 함', () => {
    // 준비: 테스트용 환경변수 설정
    process.env.OPENAI_API_KEY = 'sk-test-key';

    // 실행: 함수 호출
    const status = getEnvStatus();

    // 검증: 결과 확인
    expect(status.required.OPENAI_API_KEY).toBe(true);
    expect(status.allRequiredSet).toBe(true);
  });
});
```

## 🔍 주요 Matcher (검증 함수)

```typescript
// 값 비교
expect(value).toBe(expected)           // 정확히 같은지 (===)
expect(value).toEqual(expected)        // 객체/배열 내용이 같은지
expect(value).not.toBe(expected)       // 다른지

// Boolean
expect(value).toBeTruthy()             // true인지
expect(value).toBeFalsy()              // false인지
expect(value).toBeNull()               // null인지
expect(value).toBeUndefined()          // undefined인지

// 숫자
expect(number).toBeGreaterThan(3)      // 3보다 큰지
expect(number).toBeLessThan(5)         // 5보다 작은지
expect(number).toBeCloseTo(0.3)        // 소수점 근사값

// 문자열
expect(string).toMatch(/pattern/)      // 정규식 매칭
expect(string).toContain('substring')  // 포함하는지

// 배열
expect(array).toContain(item)          // 항목 포함
expect(array).toHaveLength(3)          // 길이 확인

// 객체
expect(obj).toHaveProperty('key')      // 속성 존재
expect(obj).toMatchObject({ a: 1 })    // 일부 속성 매칭

// 함수 (에러/호출)
expect(() => fn()).toThrow()           // 에러 발생
expect(() => fn()).toThrow('message')  // 특정 에러 메시지
expect(mockFn).toHaveBeenCalled()      // 함수 호출됨
expect(mockFn).toHaveBeenCalledWith(arg) // 특정 인자로 호출
```

## 🧪 테스트 패턴

### 1. 성공 케이스 테스트

```typescript
it('유효한 입력으로 올바른 결과를 반환해야 함', () => {
  const result = calculateSum(2, 3);
  expect(result).toBe(5);
});
```

### 2. 실패 케이스 테스트

```typescript
it('잘못된 입력으로 에러를 던져야 함', () => {
  expect(() => {
    calculateSum('a', 'b'); // 숫자가 아닌 입력
  }).toThrow('숫자만 입력 가능합니다');
});
```

### 3. Edge Case (경계값) 테스트

```typescript
it('0을 입력하면 0을 반환해야 함', () => {
  const result = calculateSum(0, 0);
  expect(result).toBe(0);
});

it('음수를 처리해야 함', () => {
  const result = calculateSum(-5, 3);
  expect(result).toBe(-2);
});
```

### 4. Mock (가짜 함수) 사용

외부 API 호출 같은 경우 실제로 호출하지 않고 가짜 응답 사용:

```typescript
// fetch API를 mock으로 대체
global.fetch = jest.fn(() =>
  Promise.resolve({
    json: () => Promise.resolve({ data: 'test' }),
  })
) as jest.Mock;

it('API 호출이 성공해야 함', async () => {
  const result = await fetchData();
  expect(result.data).toBe('test');
  expect(fetch).toHaveBeenCalledTimes(1);
});
```

## 🚀 실전 예제: RAG 서비스 테스트

```typescript
// src/lib/services/__tests__/rag.test.ts
import { searchWithRAG } from '../rag';

describe('RAG 검색 서비스', () => {
  // 모든 테스트 전에 한 번 실행
  beforeAll(() => {
    console.log('테스트 시작');
  });

  // 각 테스트 전에 실행
  beforeEach(() => {
    jest.clearAllMocks(); // mock 초기화
  });

  // 각 테스트 후 실행
  afterEach(() => {
    // 정리 작업
  });

  // 모든 테스트 후 한 번 실행
  afterAll(() => {
    console.log('테스트 종료');
  });

  it('검색 쿼리로 관련 결과를 반환해야 함', async () => {
    // Tavily API mock
    global.fetch = jest.fn(() =>
      Promise.resolve({
        ok: true,
        json: () => Promise.resolve({
          answer: '테스트 답변',
          sources: [{ title: '출처', url: 'http://test.com' }]
        }),
      })
    ) as jest.Mock;

    const result = await searchWithRAG('자동화');

    expect(result.answer).toBe('테스트 답변');
    expect(result.sources).toHaveLength(1);
  });

  it('API 실패 시 에러를 처리해야 함', async () => {
    global.fetch = jest.fn(() =>
      Promise.reject(new Error('네트워크 에러'))
    ) as jest.Mock;

    await expect(searchWithRAG('자동화')).rejects.toThrow('네트워크 에러');
  });
});
```

## 💡 팁

### 1. 테스트 이름 잘 짓기

```typescript
// ❌ 나쁜 예
it('test1', () => { ... });

// ✅ 좋은 예
it('유효한 이메일 형식이면 true를 반환해야 함', () => { ... });
```

### 2. AAA 패턴 따르기

```typescript
it('테스트 케이스', () => {
  // Arrange (준비): 데이터 설정
  const input = 'test';

  // Act (실행): 함수 실행
  const result = myFunction(input);

  // Assert (검증): 결과 확인
  expect(result).toBe('expected');
});
```

### 3. 하나의 테스트는 하나의 것만 검증

```typescript
// ❌ 나쁜 예 (여러 가지 검증)
it('여러 기능 테스트', () => {
  expect(fn1()).toBe(true);
  expect(fn2()).toBe(false);
  expect(fn3()).toThrow();
});

// ✅ 좋은 예 (각각 분리)
it('fn1은 true를 반환해야 함', () => {
  expect(fn1()).toBe(true);
});

it('fn2는 false를 반환해야 함', () => {
  expect(fn2()).toBe(false);
});
```

### 4. 테스트 격리

각 테스트는 서로 영향을 주지 않아야 합니다:

```typescript
describe('계산기', () => {
  let calculator;

  // 각 테스트마다 새 인스턴스 생성
  beforeEach(() => {
    calculator = new Calculator();
  });

  it('덧셈', () => {
    expect(calculator.add(2, 3)).toBe(5);
  });

  it('뺄셈', () => {
    expect(calculator.subtract(5, 3)).toBe(2);
  });
});
```
