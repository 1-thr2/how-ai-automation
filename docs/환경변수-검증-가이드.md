# 환경변수 검증 가이드

## 🎯 초보자를 위한 설명

**환경변수**란?
- 프로그램이 실행될 때 필요한 설정 값들 (예: API 키, 데이터베이스 주소 등)
- 코드에 직접 쓰면 보안 위험이 있어서 별도 파일(`.env.local`)에 보관
- GitHub에는 올리지 않음 (비밀 정보니까!)

## 📝 설정 방법

### 1단계: .env.local 파일 생성

터미널에서 프로젝트 폴더로 이동 후:

```bash
# .env.example 파일을 복사해서 .env.local 만들기
cp .env.example .env.local
```

### 2단계: 실제 값 입력

`.env.local` 파일을 열고 실제 값을 입력하세요:

```env
# ❌ 잘못된 예 (예시 값 그대로)
OPENAI_API_KEY=sk-proj-...여기에_실제_키_입력

# ✅ 올바른 예 (실제 값 입력)
OPENAI_API_KEY=sk-proj-abc123def456...
```

### 3단계: 필수 값 확인

**반드시 필요한 것들:**

1. **OPENAI_API_KEY**
   - 어디서 받나요? https://platform.openai.com/api-keys
   - 회원가입 → API Keys 메뉴 → Create new secret key
   - `sk-proj-`로 시작하는 긴 문자열

2. **NEXT_PUBLIC_SUPABASE_URL**
   - 어디서 받나요? https://supabase.com
   - 프로젝트 생성 → Settings → API → Project URL
   - `https://your-project.supabase.co` 형태

3. **NEXT_PUBLIC_SUPABASE_ANON_KEY**
   - 위와 같은 페이지 (Settings → API)
   - "anon public" 키 복사
   - `eyJ...`로 시작하는 긴 문자열

**선택사항 (없어도 됨):**

4. **TAVILY_API_KEY** (RAG 검색용)
   - RAG = AI가 최신 정보를 웹에서 검색하는 기능
   - 어디서 받나요? https://tavily.com
   - 없으면 기본 AI 답변만 사용

5. **DASHBOARD_PASSWORD** (관리 페이지 비밀번호)
   - 직접 만드세요 (예: mypassword123)
   - 개발 중에는 기본값 `admin123` 사용

## 🔍 검증하기

### 방법 1: 코드에서 검증

```typescript
// src/app/api/your-route/route.ts
import { env } from '@/lib/env-validator';

export async function POST(req: Request) {
  // env를 import하면 자동으로 검증됨!
  // 문제가 있으면 콘솔에 에러 메시지 표시

  const apiKey = env.OPENAI_API_KEY; // ✅ 타입 안전
}
```

### 방법 2: 상태 확인 API 만들기

```typescript
// src/app/api/env-check/route.ts
import { NextResponse } from 'next/server';
import { getEnvStatus } from '@/lib/env-validator';

export async function GET() {
  const status = getEnvStatus();

  return NextResponse.json({
    message: status.allRequiredSet
      ? '✅ 모든 필수 환경변수 설정됨'
      : '❌ 필수 환경변수가 누락됨',
    details: status
  });
}
```

그리고 브라우저에서 확인:
```
http://localhost:3005/api/env-check
```

## 🚨 에러 해결

### "OPENAI_API_KEY가 설정되지 않았습니다"

**원인:** `.env.local` 파일이 없거나, 키가 비어있음

**해결:**
1. 프로젝트 루트에 `.env.local` 파일이 있는지 확인
2. 파일 안에 `OPENAI_API_KEY=sk-proj-...` 형태로 입력되어 있는지 확인
3. 서버 재시작 (`Ctrl+C` 후 `npm run dev`)

### "sk-로 시작해야 합니다"

**원인:** OpenAI API 키 형식이 잘못됨

**해결:**
- OpenAI에서 새로 발급받은 키는 `sk-proj-`로 시작
- 예전 키는 `sk-`로 시작
- 복사할 때 공백이 들어가지 않도록 주의

### "NEXT_PUBLIC_SUPABASE_URL은 유효한 URL이어야 합니다"

**원인:** URL 형식이 잘못됨

**해결:**
- `https://`로 시작해야 함
- `.supabase.co`로 끝나야 함
- 예: `https://abcdefghijk.supabase.co`

## 💡 팁

### 1. 환경변수가 적용 안 될 때

```bash
# 서버 완전히 종료
Ctrl + C

# node_modules 삭제하고 다시 설치 (가끔 필요)
rm -rf .node_modules
npm install

# 서버 재시작
npm run dev
```

### 2. 값이 맞는지 확인하기

```typescript
// 코드에 임시로 추가해서 확인
console.log('API Key 설정됨?', !!process.env.OPENAI_API_KEY);
console.log('API Key 앞 10글자:', process.env.OPENAI_API_KEY?.substring(0, 10));
```

⚠️ **절대로 전체 키를 console.log하지 마세요!** (보안 위험)

### 3. Git에 올리면 안 되는 파일들

```
.env.local       ← 절대 올리면 안됨!
.env             ← 절대 올리면 안됨!
.env.production  ← 절대 올리면 안됨!

.env.example     ← 이건 올려도 됨 (예시니까)
```

이미 `.gitignore`에 설정되어 있어서 자동으로 제외됩니다.

## 🎓 더 알아보기

### 환경변수는 왜 필요한가요?

1. **보안**: API 키를 코드에 직접 쓰면 GitHub에 올라가서 누구나 볼 수 있음
2. **유연성**: 개발/테스트/운영 환경마다 다른 값 사용 가능
3. **팀 작업**: 각자 자기만의 API 키 사용 가능

### NEXT_PUBLIC_ 접두사는 뭔가요?

- `NEXT_PUBLIC_`으로 시작하는 변수는 **브라우저에서도 접근 가능**
- 일반 환경변수는 **서버(백엔드)에서만 접근 가능**
- Supabase URL/Key는 프론트엔드에서도 필요해서 `NEXT_PUBLIC_` 붙임

### 검증 로직은 어떻게 작동하나요?

1. `env-validator.ts` 파일을 import하면
2. Zod 라이브러리로 환경변수 검증
3. 형식이 틀리거나 필수 값이 없으면 에러 발생
4. 개발 모드에서는 경고만 표시
5. 프로덕션에서는 서버 시작을 막음 (안전장치)
